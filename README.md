# Kitted Loadout Wheel

Колесо, яке за кілька спінів збирає правдоподібний CS2-лоадаут: реальний скін,
реальний для нього флоат і сід паттерна. План розробки — у документі
«kitted.pro Loadout Wheel — план розробки».

Це окремий проєкт зі своїм тулчейном. Поки він живе в `wheel/` репозиторію
kitted.pro; щоб винести його в окремий репозиторій `kitted-wheel`, достатньо
скопіювати вміст цієї папки в корінь нового репозиторію — `.github/` уже тут.

## Команди

```
pnpm install       # у цій папці; свій pnpm-workspace.yaml відрізає її від kitted.pro
pnpm dev           # колесо на http://localhost:5173
pnpm typecheck
pnpm test          # рушій: розподіли на 100 000 ролів, жодного неможливого предмета
pnpm validate      # дані + 10 000 автоспінів через isPossible (CI: 100 000)
pnpm sync-data     # оновити data/ з ByMykel CSGO-API
pnpm build
```

## Як влаштовано

| Шлях | Що там |
| --- | --- |
| `src/engine` | Чисті функції: `rollSkin`, `rollFloat`, `rollVariant`, `rollSeed`, `rollItem`, `wearOdds`, `isPossible`, сідований генератор |
| `src/data/normalize.ts` | ByMykel → наша модель; падає на будь-якій незнайомій формі |
| `src/ui/wheel.ts` | Canvas 2D колесо; рушій вирішує результат, колесо лише анімує |
| `scripts/sync-data.ts` | Тягне ByMykel на зафіксованому коміті, валідує, і тільки тоді пише `data/` |
| `scripts/validate.ts` | Ворота CI для даних |
| `data/` | `skins.json` (одна пара «зброя + фініш» на запис) і `meta.json` з commit SHA джерела |
| `patterns/` | Таблиці сідів (фаза 4, поки порожньо) |

**Флоат.** Спочатку сирий рол за розподілом дропу (FN 3%, MW 24%, FT 33%,
WW 24%, BS 16%, рівномірно всередині відрізка), потім ремап
`min + raw × (max − min)` у float32, і лише з фінального числа — назва зношення.
Колесо зношення показує аналітичні шанси саме цього скіна (`wearOdds`).

**Відтворюваність.** Код лоадауту в URL (`#k7f2q9xa`) задає генератор, тож той
самий код у тому ж порядку слотів дає той самий лоадаут. Порядок ролів у
`rollItem` (флоат → варіант → сід) — частина цього контракту.

**StatTrak / Souvenir.** У ByMykel `stattrak` і `souvenir` означають «така
версія існує», і для ~700 скінів існують обидві. Один предмет ніколи не буває
обома: `rollVariant` обирає StatTrak (10%), Souvenir (10%, оцінка — Valve цифр
не публікує) або звичайний.

## Що ще не зроблено

- Картинки беруться з Steam CDN, а не з `public/img` (план: мініатюри 256 px у репозиторії).
- Звірка вибірки з `items_game.txt` (фаза 1) і власний парсер (фаза 6).
- Таблиці паттернів і колесо паттерна (фаза 4).
- Слоти за сторонами T / CT, пули «тільки з кейсів» / «до N $» (фаза 3).
- Хоткеї R / Enter, прозорий фон для OBS, експорт PNG (фаза 5).
